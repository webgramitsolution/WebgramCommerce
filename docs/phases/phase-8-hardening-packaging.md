# Phase 8: Hardening and ThemeForest preparation (1.0.0)

### A. Implemented

Quality gates
- `phpcs.xml.dist` at the repository root (WordPress-Extra and WooCommerce-Core rulesets, PHP 8.1 minimum, text domains `webgram` and `webgram-core`, prefixes `webgram`, `Webgram`, `WEBGRAM`, custom capabilities and escaping helpers declared). Every finding fixed: 393 errors and 288 warnings at the start of the phase, zero errors and zero warnings across 331 files at the end. Fixes were mechanical (escaping, translators comments, integer casts in `printf`, `sanitize_key` on request values, `wp_unslash`, precedence parentheses, prefixed globals in `uninstall.php`, `$tax_line` instead of the WordPress global `$tax` in the invoice template) plus targeted `phpcs:ignore` lines with a reason where the sniff is wrong for the code (WooCommerce's own `$product` global, read only admin actions that already run `check_admin_referer()` in a guard).
- PHP 8.4 syntax: `php -l` passes on every PHP file under PHP 8.4.19 (deprecation notices would show as warnings here; none did).
- WooCommerce template overrides: 8 of the allowed 12, all at `@version 9.4.0`, listed in `docs/compatibility.md`.

Security review
- `docs/security-checklist.md`: shared infrastructure, theme write paths and every Core module reviewed for nonce, capability or ownership, input sanitization, output escaping, prepared SQL, encrypted credentials and rate limits, with the file that implements each. Dependency audit: dompdf 3.1.6 pinned in `composer.lock` (Composer reported no security advisories while syncing the lock), Swiper 11.2.10 vendored.

RTL, i18n, accessibility
- `npm run build:rtl` (rtlcss) generates `main-rtl.css`, `woocommerce-rtl.css`, `shop-rtl.css`, `product-rtl.css` and `cart-checkout-rtl.css`; `inc/enqueue.php` already switches to the `-rtl` file when `is_rtl()`.
- POT files regenerated with WP-CLI: `webgram-theme/languages/webgram.pot` (905 strings) and `webgram-core/languages/webgram-core.pot` (1234 strings).
- `wpml-config.xml` for both products (translatable options, post types and taxonomies).
- `docs/accessibility.md`: what exists (skip link, focus-visible, reduced motion, dialog semantics and focus handling in theme drawers, keyboard navigation in the desktop menu, labelled icon buttons, live regions) and two follow ups (Tab cycling in the Core quick view, reels viewer and assistant window; `aria-describedby` on Core form errors).

Packaging
- `scripts/package.sh`: builds `dist/webgram-core.zip` (git archive plus `composer install --no-dev --prefer-dist` with VCS metadata, tests and docs pruned from vendor), `dist/webgram-theme.zip` (git archive with `assets/src`, `node_modules` and npm files removed, compiled assets from the working tree, and the Core zip plus a JSON manifest bundled at `plugins/`), `dist/webgram-child.zip` and `dist/documentation/` (user guide, hooks reference, licensing, compatibility, deployment guide, license).
- Theme `inc/admin/class-plugin-installer.php`: own installer for the bundled Core (no TGMPA). `install_plugins` and `activate_plugins` plus a nonce, `Plugin_Upgrader` with the silent AJAX skin, states resolved by pure `resolve_state()` (no bundle, install, activate, update when the bundled version is newer, current), button on Webgram > System status, notices with the upgrader error when something fails. The manifest version is read first, the zip header second.
- Theme `inc/admin/class-demo-importer.php` and `webgram-theme/demo/`: Webgram > Demo import with selectable, idempotent steps: theme settings plus header and footer presets (`theme-settings.json`), 30 original flat placeholder PNGs generated by a script (`images/`), 12 sample products in 4 categories through WooCommerce's own `WC_Product_CSV_Importer` with identity column mapping and images matched by file name (`products.csv`), 4 blog posts (`posts.json`), Core content through `webgram/demo/import`, pages (Home from `homepage-gutenberg.html` with the slider id injected, Blog, Help, Track Order and Bulk Order with their templates, About, Contact) and reading settings, primary menu with Shop and category children assigned to primary, secondary and mobile locations plus a footer menu, and footer block widgets (`widgets.json`). Nothing is deleted or overwritten.
- Core `Support\DemoContent`: listens to `webgram/demo/import`, creates the home slider (two slides with per device images and benefit rows), six testimonials linked to products, two coupons (`WELCOME10`, `FREESHIP`) through `WC_Coupon`, and the wishlist and compare pages through the new `PageSetup::create_page()`; reports the slider id and a summary through `webgram/demo/context`. Only modules that are active create content.
- `scripts/hooks-reference.php` scans both products with a balanced parser (dynamic hook names shown as `{placeholders}`) and writes `docs/hooks-reference.md` (212 hooks).
- Documentation: `docs/user-guide.html` (buyer documentation, self contained), `docs/compatibility.md`, `docs/security-checklist.md`, `docs/accessibility.md`, `docs/deploy-hostinger.md` (Nginx server block with the `webgram-invoices` deny rule, PHP-FPM, Redis, cron, Git and rsync deployment, migrations, backups), `docs/licensing.md`, `LICENSE.md`.
- Versions: theme 1.0.0 (`WEBGRAM_MIN_CORE_VERSION` 1.0.0), Core 1.0.0 with changelog, child 1.0.0, `package.json` 1.0.0.

### E. Errors found and fixed

- PHPCS ruleset referenced sniffs not installed (PrecisionAlignment, PHPCompatibilityWP): removed one, installed the other and registered `installed_paths`.
- Short prefixes `wg` and `wgc` in the ruleset triggered `ShortPrefixPassed`: removed them; no code needed them (CSS classes are strings, not globals).
- Composer's first install cloned packages from source (with `.git` and tests) because dist downloads were unavailable, producing a 50 MB zip: switched to `--prefer-dist` and pruned VCS metadata, tests and docs; the zip is 5 MB.
- `composer.lock` was out of date with `composer.json` (platform settings): synced with `composer update --lock`.
- `Webgram_Demo_Importer::menu()` collided with the submenu callback name: renamed the nav menu helper to `nav_menu()`.
- Importer exceptions carried untranslated, unescaped messages (PHPCS): messages now use `esc_html__()`; temporary files removed with `wp_delete_file()`.

### F. Compatibility concerns

- `Plugin_Upgrader::install()` with `overwrite_package` needs WordPress 5.5+ (the theme requires 6.4).
- `WC_Product_CSV_Importer` is a WooCommerce internal class loaded from `includes/import/`; the demo importer guards on `class_exists( 'WooCommerce' )` and requires the file explicitly. If a future WooCommerce version moves it, only the products step fails and the report shows the message.
- The theme zip carries the Core zip (5 MB). ThemeForest accepts bundled plugins; the buyer can also install `webgram-core.zip` separately.
- Theme Check and Envato Theme Check could not be run here (they need a WordPress install); see Not tested.

### H. Known limitations

- The demo importer does not ship a WXR file or an Elementor kit import step; product data goes through WooCommerce's CSV importer and the homepage is the Gutenberg version, with `homepage-elementor.json` importable manually under Templates. Reels are not created by the demo (they need video files).
- Placeholder images are flat coloured shapes with a label; the marketplace preview needs real photography before submission.
- Screenshot and preview images for the listing are not part of the repository.
- Core quick view, reels viewer and assistant window lack Tab cycling inside the dialog (theme drawers have it).
- The security checklist is a code review, not a penetration test.
