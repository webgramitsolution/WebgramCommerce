# Phase 1: Theme Settings panel, header and footer builders, mega menu, mobile menu, Site Tools, location picker (0.2.0)

### A. Implemented

Webgram Theme
- Theme Settings framework (`inc/settings/`): one autoloaded option `webgram_theme_settings`; tab registry with 20 theme tabs (General, Layout, Header banner, Mobile bottom navbar, Mobile menu, Search, Sticky navigation, Page title, Footer, Typography, Styles and colors, Blog, Shop, Product archive, Single product, My account, Social profiles, Performance, Custom CSS, Other) declared in `inc/settings/tabs/*.php`; Core tabs join through `webgram/settings/tabs` with their own `values`, `save` and `reset` callbacks. Field types: text, textarea, html, number, range, switch, select, radio, radio_image, multicheck, sortable, color (hex and rgba), image, page, menu, icon, html_block, url, email, code (WordPress code editor), dimensions (device tabs), typography, repeater (drag sort, collapse, max), secret, heading, link, info. Dependencies via `show_if`. Sanitizer per type in `Webgram_Settings_Sanitizer`. Admin panel (`Webgram > Theme Settings`) with vertical tab list, sticky save bar, per-tab reset, unsaved changes guard, "View site" link.
- Migration from Phase 0 Customizer theme_mods (`Webgram_Settings_Migration`, one-time on admin_init or theme switch). Customizer reduced to Site Identity plus a link section. `webgram_option()` and the CSS token generator repointed to the new option; generator now emits heading sizes per device, menu and button typography tokens, shadow scale, custom font `@font-face`, Custom CSS (all, tablet, mobile) inside the same inline block.
- Import / Export / Reset page: JSON export of theme settings, header layout, footer layout and Core settings (through `webgram/export_data`); import validated against field schemas (unknown keys ignored, every value sanitized); global reset with confirmation; per-tab reset on each tab.
- Header builder (`inc/builders/`): element base class plus array-defined adapter for Core elements; registry of 22 theme elements (logo, primary menu, secondary menu, categories dropdown, search bar, search icon, track order, bulk order, help, cart, account, announcement marquee, social icons, button, text, HTML Block, phone, divider, spacer, mobile menu toggle, currency slot, language switcher); Core adds deliver-to (and later wishlist, compare, mic) through `webgram/header/elements`; reserved Core ids survive Core deactivation. Layout option `webgram_header_layout`: desktop and mobile, rows top/main/bottom with left/center/right areas, per-row settings (height, background, text color, border, shadow, container), sticky config, element settings. Sanitizer strips unknown ids, dedupes per device, clamps row settings, rejects unsafe CSS values. Five presets (Store, Classic, Minimal, Two rows, Centered logo); the Store preset reproduces spec 4.1 (marquee top bar, logo, deliver to, search, track order / bulk order / wishlist / compare / help / cart / account, red secondary bar; mobile: hamburger, logo, search icon, cart; full-width search row).
- Header builder page (`Webgram > Header Builder`): drag and drop from a grouped palette into areas, reorder, remove, one instance per device, click to open element settings, row settings panel, device tabs, preset apply, JSON serialization on save. Same page class drives the Footer Builder.
- Renderer: rows as `wg-header__row--{name}`, areas as `wg-header__col--{area}`, elements wrapped in `wg-header__el wg-header__el--{id}`; desktop and mobile panes; consecutive sticky rows grouped in `wg-header__sticky` (position sticky, shadow, shrink to 60px, hide on scroll down, admin bar offset, optional on mobile).
- Marquee top bar: messages repeater (icon, text, link), modes marquee / static / slide, speed in px/s, direction, pause on hover, gap, separator (dot, line, none), reduced-motion fallback. CSS animation on a duplicated track; JS only clones content to fill the width.
- Search: pill bar with mic slot (`webgram/search/input`), clear button, live results dropdown (products with thumb and price, categories with counts, articles, popular searches before typing, keyboard navigation, view all link) through `wc-ajax=webgram_live_search` (WooCommerce product search including SKU, admin-ajax fallback without WooCommerce), nonce, 5 minute transient cache. Full-width search overlay for the search icon element and the bottom navbar.
- Mega menu: fields on Appearance > Menus items (top level: panel on/off, width container/full/custom, columns 2 to 6; column: heading style, image, description, promo block image/heading/link; any depth: badge text and color, icon, hide label). Walker outputs `wg-nav` dropdowns and `wg-mega` panels with columns, images, promo blocks and badges, ARIA attributes; cached per menu in a transient (current item marked by JS from the URL), flushed on menu save. Desktop JS: hover intent, Enter/Space/ArrowDown open, Escape closes, Left/Right move between top items, touch first-tap opens.
- Mobile drawer: left or right, width, Menu | Categories tabs (WooCommerce categories with thumbnails, optional subcategory accordion), optional search field, account links, currency and language slots, accordion walker with toggle buttons.
- Mobile bottom navbar: items repeater (home, shop, search, wishlist, compare, cart, account, menu, custom), light/dark/primary style, labels on/off, hide on scroll down, safe-area padding, cart count badge, body padding so content is not covered.
- Footer builder (`Webgram > Footer Builder`): columns row (1 to 6 columns, first column wider option, padding, alignment) and bottom row (left/center/right, border, background); elements: logo (light variant), brand description, three menu slots with headings, widget areas (count from Theme Settings), social icons (circle outline with labels, brand colors), newsletter (plugin hook or form shortcode, no own list), payment icons (12 SVG badges), trust text, copyright with `{year}` and `{site}`, contact info, text, HTML Block, button. Store preset reproduces spec 4.9.
- Floating social sidebar (brand colors, per-device visibility), back to top button (offset), header banner (text, image or HTML Block; above or below header; close remembered by cookie or session), preloader, page title band with breadcrumb (Rank Math, Yoast, WooCommerce or theme trail), boxed site layout, sidebar width, performance toggles (emoji, embeds, font preload, critical header CSS file hook, CDN prefix), forced RTL preview.
- Templates: 404 page from settings or Core Layout, index/archive/search/page with the page title band, header.php and footer.php hooking Core header and footer Layouts (`webgram/layout_for`), blocks rendered through `webgram/html_block`.
- Assets: 102 SVG icons plus 12 payment badges; SCSS partials for header, marquee, mega menu, search, drawer, bottom nav, floating UI, page title, footer, Core components; JS modules header, marquee, menu, search, misc, drawer tabs. Admin: `assets/admin/settings.css`, `settings.js`, `builder.js` (vanilla, jQuery only for the WordPress color picker).

Webgram Core
- Admin pages attach under the theme's `Webgram` menu when the theme declares `admin_menu` and `settings_panel` in its `webgram-core` theme support; otherwise Core keeps its own top-level menu. Core Settings renderer extended for the shared schema (switch, radio, multicheck, page, html_block, code, heading, link, info) so Site Tools is configurable on any theme. `Helpers::css_class()` prints `wgc-*` plus `wg-*` when the theme styles Core. Fixed: `webgramCore` front-end data was never localized when the theme provided styles.
- `site_tools` module (implemented): HTML Blocks CPT `wg_block` with shortcode `[webgram_block]`, `webgram/html_blocks` list and `webgram/html_block` render filters, Elementor support, shortcode column; Layouts CPT `wg_layout` with type, priority, devices, login state and a conditions table (include/exclude by entire site, front page, shop, products, categories, tags, brands, pages, posts, post types, blog, search, 404), pure `Conditions` engine and `Resolver` (cached candidates, per-request pick) answering `webgram/layout_for`; promo popup (HTML Block or content, side image, width, delay/scroll/exit triggers, frequency cookie, device and page targeting); cookie notice (accept, GDPR reject, policy link, positions, remember days, `wg:cookie-consent` event); age verification (yes/no or date of birth, redirect, remember days, background); maintenance and coming soon (page, HTML Block or built-in page with countdown, 503 header, allowed roles, admin bar indicator); white label (panel name, logo, hidden pages); custom JS (header and footer, `unfiltered_html` required, printed with `wp_add_inline_script`); optional portfolio CPT. All settings appear as Core tabs inside Theme Settings (Promo popup, Age verify popup, Cookie law info, Maintenance, White label, API integrations, Custom JS, Layouts, HTML Blocks, Portfolio) and are included in export/import.
- `woo_enhancements` module (implemented, pincode part): `wg_pincodes` table repository; `PincodeChecker` with per-country validation (India 6 digits, US, GB, CA, EU formats, generic fallback), delivery modes "all deliverable" and "imported list", ETA and COD defaults, `wc-ajax=webgram_pincode_check`; CSV import page `Webgram > Pincodes` (header mapping, dedupe, batch upsert, sample CSV in `data/`); `Location` picker: header deliver-to pill (also a header builder element and `[webgram_location]` shortcode), modal with pincode input and optional "Use my current location", cookie `wg_location` (30 days) plus user meta, `webgram_core/location/saved` action, `wc-ajax=webgram_location_resolve` and `webgram_location_geocode` with rate limits; reverse geocoder interface with Null and OpenStreetMap Nominatim adapters (attribution, contact email, 30 day cache), extensible through `webgram_core/geo/adapters`. ### E. Errors found and fixed

- Phase 0 `Assets::enqueue_base()` returned before localizing `webgramCore` when the theme provided styles; Core JS would have had no nonce or endpoints. Fixed.
- Header sanitizer stripped Core-provided elements (deliver-to, wishlist, compare) from stored layouts whenever Core was inactive; they are now reserved ids skipped only at render time.
- Indian pincodes typed with a space ("400 001") failed validation; spaces are removed for numeric postal systems.

### F. Compatibility concerns

- Mega menu markup is cached per menu; plugins that inject per-user content into menu items should disable the cache with `add_filter( 'webgram/menu_cache', '__return_false' )`.
- Promo popup device targeting uses the User-Agent server-side; with full-page caching the first cached variant wins. Frequency and dismissal are handled in the browser and work under caching.
- Cookie notice and age gate are also printed on cached pages; JS hides them when the cookie exists.
- Maintenance mode never blocks wp-login.php, admin, REST, AJAX or cron; caching plugins should be purged when toggling the mode.
- Nominatim is limited to one request per second by its usage policy; the adapter caches results for 30 days and the AJAX endpoint is rate limited (10 per minute per IP hash). High traffic stores should use a paid adapter through `webgram_core/geo/adapters`.
- `perf_cdn_prefix` rewrites the theme directory URI only; plugin assets are left to the caching plugin.

### H. Known limitations

- Live preview inside the panel is not provided (by spec: "View site" link and unsaved changes guard instead).
- The header builder allows one instance of each element per device.
- Layout conditions use a fixed table of rows (no dynamic add button); empty rows are ignored.
- Portfolio uses the theme's generic archive and single templates; dedicated portfolio templates are deferred.
- Wishlist and compare header elements and the mic button only appear when their Core modules ship (Phases 4 and 6); the builder palette shows them as unavailable until then.
- `critical.css` for the "inline critical header CSS" option is not generated yet (the hook reads the file if present; Phase 8 packaging will generate it).
- No reverse geocoding provider beyond Nominatim; paid providers plug into the interface.
