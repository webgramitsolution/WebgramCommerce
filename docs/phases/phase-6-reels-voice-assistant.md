### F. Compatibility concerns

- Providers are called through `wp_remote_post` (WordPress HTTP API) rather than vendor SDKs, per the build specification; request shapes follow the current Anthropic Messages API (adaptive thinking default, `output_config.effort`, `fallbacks: "default"` with the `server-side-fallback-2026-07-01` beta header on Opus 5 and Fable models). Store owners on models that reject those fields can change the model name or adjust the request through `webgram_core/ai/request`.
- The assistant REST endpoints require the REST nonce, so full-page caches must not cache the localized `webgramCore` data with a stale nonce; the theme prints it on every request (nonces last 24 hours).
- Reels in iframes (YouTube, Vimeo, Cloudflare, Bunny) cannot report completion; only MP4 reels emit `reel_complete`. Third-party cookie and autoplay policies still apply to iframes.
- Voice search depends on the browser; Chrome and Edge send audio to Google and Microsoft services for recognition, which the store's privacy policy should mention.
- The rule based provider searches with WooCommerce's default product search (`s`), so relevance is limited to titles and content; a search plugin that filters `wc_get_products` improves it.
- Order status answers only for logged in customers who own the order; guests are told to log in.

### G. Not tested

- Nothing in this phase ran inside WordPress or a browser: reel metabox and video picker, upload limit, row autoplay and IntersectionObserver behaviour, mute toggle, viewer feed and swipe, product sheet, add to cart from reels, iframe adapters against real videos, product page reel row, mic button in Chrome and hiding in Firefox, speech results and auto submit, assistant launcher and bundle loading, consent flow, REST calls with the nonce, rate limit and budget responses, provider calls against live Anthropic, OpenAI or Gemini APIs (only request and response shapes are unit tested), tool execution against real products and orders, table creation through activation and migration, retention cron, privacy export and erase, inline widget, theme styles at desktop and mobile widths.
- Acceptance scenarios ("Show me wall decor under 2000" against a live store; rule based answers without a key; mic hidden in Firefox; reel viewer add to cart; disabling modules removes their assets) not run end to end.
- PHPCS, Lighthouse, accessibility audits.

### H. Known limitations

- Responses are not streamed (non streaming with a typing indicator, provider timeout 20 seconds), as planned for v1.
- The server side speech engine is an interface only; no transcription provider ships in v1.
- Analytics events from reels and the assistant are emitted client side and server side but stored only once the Phase 7 Analytics collector exists.
- The Gemini and OpenAI default model names are examples that the store owner can change; provider pricing and model availability are the store owner's responsibility.
- Conversation history sent to providers is capped at 12 turns; older context is not summarized.
