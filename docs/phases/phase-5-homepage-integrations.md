# Phase 5: Homepage sections, slider, Instagram, testimonials, Elementor and Gutenberg (0.6.0)

### A. Implemented

Webgram Core
- `Support\ProductQuery`: one query for every section, widget, block and shortcode. Sources recent, best_selling (total_sales), trending (`_wg_trend_score` with best sellers then newest fill), on_sale, featured, top_rated, category, tag, ids (order kept), random. Normalizes untrusted arguments (limit 1 to 48, slugs, ids, in stock), builds `wc_get_products` arguments, caches id lists by argument hash in cache group `products` for 15 minutes, flushed on product save, stock changes and deletes. `Support\Trending`: daily cron (`webgram_core_trending_daily`, registered for cleanup on deactivation) scoring products from view buckets supplied by `webgram_core/trending/views` (Analytics, Phase 7) and paid orders of the last 14 days, decayed by age (pure `scores()`), stored on the top 500 products, overridable through `webgram_core/trending/scores`.
- Slider module (`wg_slider` post type under the Webgram menu): slides metabox repeater (desktop, tablet and mobile images, small text, heading, description, two CTAs, benefit icon row of up to 4 "icon|text" lines, text align, vertical position, content animation fade/slide/zoom, overlay color and opacity, text color; add, remove, reorder, collapse), settings metabox (autoplay, delay, pause on hover, loop, arrows, dots, lazy, full width, effect fade/slide, height mode ratio/fixed/viewport, desktop and mobile ratios), pure sanitizers, list columns with thumbnails and shortcode. Renderer: Swiper 11.2.10 vendored in `assets/vendor/swiper` (registered once, enqueued only where a slider renders), `<picture>` with mobile and tablet sources falling back to the desktop image, `fetchpriority="high"` and eager loading on the first slide, the rest lazy, aspect ratio CSS variables printed inline so the slide box is fixed before images load (no CLS), overlays, per-slide content animation, keyboard and reduced motion support, first slide heading as `h1`. Shortcode `[webgram_slider id=""]`, widget and block through the Integrations registry.
- Instagram module: settings tab in the theme panel (fallback fields on the Core screen) with mode API or manual, Instagram Business Account ID, long-lived token (`secret`, stored encrypted, empty submit keeps the stored value), Graph API version (default v21.0), cache hours, "Test connection" (admin-post with nonce, calls `GET /{ig-user-id}?fields=username,media_count`, stores the last error for the notice and the status text), manual posts repeater (image, link, caption; textarea "image | link | caption" on the fallback screen), display defaults (title, count, columns, grid or slider, caption on hover, Follow link and text). `Api` client with pure URL builder and payload normalizer (videos use the thumbnail, only https media and permalinks accepted), `wp_remote_get` with 10 second timeout, cached in group `instagram`, errors logged and shown to admins, frontend falls back to manual items. Token refresh every 30 days through a custom cron schedule (`GET /refresh_access_token`, Instagram Login tokens; the UI explains that Facebook Login tokens must be regenerated). Renderer: grid or scroll-snap slider, square tiles with hover icon and caption, video badge, "Follow Us" outline pill, lazy images, no external script. Shortcode `[webgram_instagram]`, widget and block.
- Integrations module: `Registry` collects section definitions from `webgram_core/elementor/widgets` (id, title, icon, category, controls with types text, textarea, number, switch, select, url, color, image, product, category, tag, post, repeater, html; `render` callable or `shortcode`), normalizes controls, sanitizes arguments per type (pure), renders with `webgram_core/section/args` and `/html` filters. Three entry points share it: `Shortcodes` (`[webgram_{id}]` for every definition without its own shortcode), `Blocks` (server-rendered `webgram/{id}` blocks with attributes derived from the controls, a "Webgram" block category and one generic editor script that builds inspector controls, including media pickers and repeaters, and previews through ServerSideRender), and `Elementor\Loader` plus `SectionWidget` (one `Widget_Base` subclass instantiated per definition; the definition is resolved from the registration arguments or from `widgetType` when Elementor rebuilds saved widgets; controls map to Elementor control types including SELECT2 pickers for products, categories and tags and REPEATER for repeaters; "Webgram" and "Webgram Product Layout" categories). Elementor is loaded only when present; module settings toggle Elementor widgets and blocks separately.
- Core sections (`Sections`): Product Grid, Product Slider, Trending, Best Sellers (dark band with the two-line "BEST / Sellers" title, 4 cards, dots, View All under the band), Mega Saver Packs (tag or category source), Featured, all with shared heading controls (title, subtitle, align, View All link that defaults to the shop or category), source, categories, tags, ids, limit, columns, layout, in stock; Categories (top level, selected or all, count, columns, circle/square/rounded, ribbon or below label, hide empty, count); Coupons Row (codes or all live coupons, headline from the Coupons module, minimum and expiry, copy button); Trust Badges (repeater of image, title, link; grayscale until hover); Testimonials (new `wg_testimonial` post type with name, quote, photo, label, rating and product link; dark band or light, visible cards, stars). Cards inside product sections render through `content-product.php`, so the active theme's card is used everywhere. Templates in `templates/sections/`, overridable by themes, with fallback CSS for non-Webgram themes.
- Single product layout widgets (`ProductParts`, category "Webgram Product Layout") for Core Layouts: title (tag), price, rating, short description, add to cart, gallery (theme gallery hook or WooCommerce images), meta, stock, data tabs, description, related and upsells (limit, columns), breadcrumb, and "Webgram Product Section" (coupon box, contact seller, delivery check, specifications, payment strip, trust seals, share through the theme's summary hooks). `Preview` resolves the current product or the latest published one inside editors.
- `Admin\PageSetup` reused; `SettingsBridge` extracted so any module can attach shared-schema tabs to the theme panel with Core-owned storage and flatten them for the Core screen (lazy definitions so admin URL helpers are not needed at boot).

Webgram Theme
- Presentational sections in `template-parts/sections/`: section heading (CSS ornament, subtitle, align, link with arrow icon, tag), banner (image and mobile image, heading, text, button, align, min height, overlay, text color, rounded), benefits row (icon, title, text; plain row or cards; defaults Great Value, Nationwide Delivery, Secure Payment, Buyer Protection, 365 Days Help Desk), blog grid (16:10 cards, count, columns, category, excerpt, View All), about split (image 40 percent left or right, heading with ornament, paragraphs, 3 benefit cards, red CTA with arrow icon), marquee strip (same marquee component as the top bar with its own colors, speed and separator). `Webgram_Sections` declares them once: with Core active they are handed to the registry (Elementor widgets, blocks, shortcodes); without Core the theme registers the same server-rendered blocks with its own small editor script (`assets/js/blocks.js`).
- Carousel module (`carousel.js`, component `data-wg-component="carousel"`): turns section rows into scroll-snap carousels with arrows and dots. Modes: mobile only (product rows: 2.2 cards visible under 768px), always (slider layout), dots (band, testimonials), overflow (category circles). Core templates print the attribute, so any theme without the module keeps a plain grid or CSS scroll row.
- Styles (`components/_sections.scss`): product rows, Best Sellers band, category circles with ribbon labels and hover scale, coupons row, trust badges, testimonials (dark band, photo left 40 percent, gold stars, dots), Instagram grid with hover overlay and Follow pill, about split, blog grid, benefits row (28px red outline icons), banner, strip, carousel chrome. New image size `webgram-card-wide` (800x500).
- "Sync tokens to Elementor" button on the theme dashboard (admin-post with nonce and capability): writes the theme colors and body and heading font families into the active Elementor kit as "Webgram" global colors and fonts, replacing previous Webgram entries only, and clears the Elementor CSS cache.
- Demo content: `demo/homepage-gutenberg.html` (block markup of the 12 reference sections), `demo/homepage-elementor.json` (Elementor page template with the same widgets) and a README; the one-click importer with placeholder images is Phase 8.

### E. Errors found and fixed

- Instagram settings built the "Test connection" URL at boot, which needs admin URL helpers; `SettingsBridge::attach()` now accepts a callable so definitions resolve only when the settings panel renders.
- Harness expectation for nested repeater defaults was wrong (default is 1, not 0); corrected.
- Blog grid referenced a non-existent image size; `webgram-card-wide` registered.
- The strip section first used its own marquee markup; rewritten to the theme's marquee component so `marquee.js` and the top bar styles apply.

### F. Compatibility concerns

- Swiper is enqueued only where a Webgram slider renders. A theme or plugin that already loads Swiper under another handle would load it twice on those pages; `webgram_core/slider/config` and dequeueing `webgram-core-swiper` are the escape hatches.
- Elementor widgets share one PHP class; Elementor keys widgets by name, and the class resolves its definition from `widgetType`, so saved pages keep working as long as the definition id exists. Removing a definition leaves an empty widget in the editor instead of a fatal.
- Product sections render cards through `content-product.php`; themes that rely on `woocommerce_shop_loop` hooks for extra card content need those hooks inside their card template.
- Blocks are registered from PHP with attribute schemas instead of one `block.json` per block; the behaviour is the same (server rendered, editor script shared), and Phase 8 packaging can emit `block.json` files from the registry if the ThemeForest reviewer asks.
- Trending scores need the daily cron; until it runs (or without sales), the trending section fills from best sellers and newest products.
- Instagram API mode depends on Meta app review and a Business or Creator account; the retired Basic Display API is not supported by design.

### H. Known limitations

- Elementor widgets expose content controls only; styling relies on the theme tokens (synced to Elementor globals) rather than per-widget style tabs.
- Product and category pickers in Elementor list up to 200 products and 300 terms; larger catalogs use the ids or slug text fields.
- Block inspector category and tag pickers are comma separated slug fields, not term search boxes.
- Testimonial slider and product rows use CSS scroll-snap with the theme's carousel chrome, not Swiper; the hero slider is the only Swiper instance.
- Demo content ships as block markup and an Elementor template; images, sliders and testimonials must exist on the site (ids are placeholders) until the Phase 8 importer.
- Reels row (item 7 of the homepage) arrives with the Reels module in Phase 6.
